Von Tim Stukenbröker (Sitzung 16.11.2026):
- **Branch:** Es bleibt beim Branch `m3` (CLAUDE.md nennt `modul/m3-projekte`). Jeder Schritt ist ein eigener Commit. Gepusht wird erst, wenn ein Programmteil abgeschlossen ist (nach jedem AP).
- **Fremdschlüssel auf `mitarbeiter`:** `projekt.projektleitung_id` und `projektzuordnung.mitarbeiter_id` sind nur Zahlenspalten ohne Datenbank-Fremdschlüssel, weil die Tabelle `mitarbeiter` zu M1 gehört und M3 keine fremde Entity benutzen darf. Ob die Person existiert, prüft später der Service über `MitarbeiterAuskunft` (AP2).
- **Filterabfrage:** eine JPQL-Abfrage mit optionalen Parametern (ein leerer Filter wird ignoriert).
- **Schlüssel von `projektzuordnung`:** zusammengesetzter Schlüssel (`mitarbeiter_id` + `projekt_id`) als kleine verschachtelte Klasse in `Projektzuordnung`, keine eigene Datei.
- **Zwei Repositories:** `ProjektRepository` und zusätzlich `ProjektzuordnungRepository` (Spring Data legt ein Repository je Entity an).
- **Arbeitsregeln:** Code einfach und gut erklärbar, mit verständlichen deutschen Kommentaren. Nur an M3 arbeiten, bei Unklarheiten oder Kontakt zu anderen Modulen vorher fragen, keine Annahmen.
